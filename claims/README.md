# claims/ — shared-service claim registry

One `claims/<service>.md` file per shared service (never hand-edited — see the footer of each file). Regenerated by `python3 scripts/claims.py sync-registry`; `--check` fails if the checked-in files drift from what regenerating would produce. Full protocol: `docs/DESIGN.md` §4.

Two kinds of service:

- **crate** — a workspace crate reachable via path dependencies from >= 2 of the app crates (`example-app`), rule (a). Derived from `cargo metadata`.
- **declared** — a non-crate shared unit listed in `claims/REGISTRY.toml`, rule (b).

Current services: ci-workflows, shared-ui, workspace-manifests

## Live claim state lives in the refs, not here

A claim record is never committed on a working branch. It is the sole file of an orphan commit pushed to `refs/claims/<service>` on `origin`, mirrored to `$(git rev-parse --git-common-dir)/claims/<service>.claim` for offline reads.

## CLI cheat-sheet

```
python3 scripts/claims.py claim <service> --intent "<one line>" [--ttl-hours 8] [--takeover]
python3 scripts/claims.py renew <service> | --all-mine | --branch <b>
python3 scripts/claims.py release <service> | --branch <b> | --all-mine [--force]
python3 scripts/claims.py list [--json] [--offline]
python3 scripts/claims.py services --files <f>... | --base <ref> --head <ref>
python3 scripts/claims.py check --base <ref> --head <ref> --branch <name> [--branch <name> ...] [--actor <login>]
python3 scripts/claims.py sync-registry [--check]
```

## Exemptions from claim enforcement (`claims.py check`)

- Docs-only diffs (every changed file under a docs prefix or with a docs suffix — see `claims.docs_prefixes` / `claims.docs_suffixes`).
- Lockfile-only diffs (`claims.lockfile_names`).
- Diffs whose actor is in `claims.exempt_actors`.

These enforce *exclusive landing*, not exclusive editing — two branches can still edit the same service concurrently; only the claim holder can land.
